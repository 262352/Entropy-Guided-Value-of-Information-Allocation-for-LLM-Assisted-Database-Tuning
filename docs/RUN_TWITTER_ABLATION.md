# Twitter：50轮机制消融

本轮只准备代码、审计现有数据和进行离线验证。真实数据库调优与付费LLM调用由用户运行。
不重跑MCTuner，不覆盖旧结果；当前数据库接受连接，检查时没有活跃的Twitter/BenchBase进程。

## 先看现有结果

| 方法 | 完成轮数 | 搜索峰值TPS | 最佳轮次 | 最佳配置3次复测中位数TPS |
|---|---:|---:|---:|---:|
| 新版CogniTune stable-v1 | 50 | 23719.22 | 40 | 22635.94 |
| 旧版CogniTune v3 | 50 | 23090.30 | 11 | 22188.86 |
| 上一组MCTuner | 50 | 23631.03 | 42 | 23233.18 |
| 新一组MCTuner | 2 | 23504.89 | 2 | 尚未完成 |

新版峰值比上一组MCTuner高0.37%，但复测原始中位数低2.57%。两者跨天运行、各自默认
基线分别为15393.62和15902.70 TPS；新版复测CV约3.26%。这些数据不足以确认方法优劣。
新版的最佳配置复测并非稳定复现23719 TPS。不要只凭峰值认定改进成立。

过程审计发现：

- 活动集合由旧版40种降为5种，换入8个参数；换出前均已有实际覆盖记录。
- 40次自适应评测中，局部覆盖11次、重入3次、信息选择9次、qLogNEI选择17次。
  14次预留试验占35%；局部覆盖产生1次新峰值，重入没有刷新峰值。这是预算取舍的线索，
  尚不能证明重入无效，因为其结果也可能影响后续模型和参数安排。
- 真正的半宽更新仅3次，都是0.15到0.12的收缩，没有观测到反馈触发的扩展。
  参数分别为effective_io_concurrency、default_statistics_target、bgwriter_lru_maxpages。
  “范围会更新”已执行，但“能否在错误先验下有效扩大搜索”仍缺少实证。
- 21轮的改进来自全局参考，23轮来自专家参数组，40轮来自局部覆盖；最终峰值并非直接联合提议。
- 联合评议89次、同意32次，直接联合候选没有被最终选中。不能据此排除已确认参数组的
  间接作用，但值得在后续检查其LLM成本与进入候选池后的实际利用率。
- 单轮实际唯一候选数86到95，中位数90.5；“候选配额”不等于去重和合法性检查后的
  实际候选数。新增诊断同时记录这两个量。

## 消融定义

| 名称 | 唯一主要干预 | 保留的机制 |
|---|---|---|
| `full` | 当前完整stable方法，重新独立运行 | 全部 |
| `fixed_knobs` | 冻结bootstrap选出的活动集合；关闭预留的非活动参数重入试验 | 专家反馈提议、推荐区域更新、分配、信息选择、活动参数覆盖 |
| `fixed_regions` | 每个专家对每个参数首次进入时确定的中心、半宽、推荐选项保持不变 | 活动集合更新、逐轮专家请求、参数组提议、分配和选点评估 |
| `uniform_budget` | 参数组候选配额均匀分配，整数余数按固定次序分配；专家提示中的配额也均匀 | 多专家、组结构、等规模审计、共享GP、信息选择、参数和区域更新 |
| `nei_only` | 关闭信息增益对真实试验选择的影响，常规轮次取最大qLogNEI | 等规模审计与后验分配、动态参数/区域、原有覆盖与重入预留 |

`fixed_regions` 的细节：冻结的是**推荐区域**，不是整个合法配置空间。
保留各版本共有的10%全域探索、全局参考、覆盖和重入通道。冻结后，普通显式补丁先投影到
冻结区域，按组采样不再用新补丁值重置中心；区域外的联合补丁被记录并拒绝，不在一致性
评议后偷偷改变含义。新引入参数在首次提议时初始化自己的区域；再次进入仍使用已存区域。
因此，该消融测试推荐区域持续更新的作用，不测试“完全禁止范围外探索”的作用。

`nei_only` 仍计算信息诊断，以保持可比日志和随机流使用；它只取消信息选择，不取消
全部探索行为。`uniform_budget` 检验反馈分配的作用，**不能单独证明多专家优于单专家**。
五种设置是逐项移除机制的局部对照，不是完整析因实验。

## 实验控制

- 每个版本50次真实评测，含相同的10个持久化IID初始配置。初始配置重新测量，TPS不复用。
- 每版独立3次默认预检、3次最佳配置复测、3次结束后的默认检查，均在50轮预算外。
  五版合计250次调优评测，另有45次检查/复测；LLM请求不计入数据库评测预算，但保留请求缓存。
- 同一个deepseek-flash服务、工作负载、数据模板、60参数域、15秒预热+60秒测量、测量成功吞吐量。
- `full` 必须新跑：旧stable实验在第29次前修复过离散参数接口，不作为本批消融的严格控制组。
- 共用已有配置设计与准备信息；不复用任何实验的TPS、默认性能、专家反馈或控制器状态。
- 所有版本串行访问同一实例；实例锁阻止与其他真实实验并行。波动和漂移检查继续生效。
- 参数、变体身份写入协议及检查点；变体不匹配拒绝续跑。每次会话保存实现文件SHA256。
- 当前为seed=0的诊断，不足以支撑统计显著性。先定位机制，再决定重复运行与交互消融。
  LLM提议和各次真实测量具有随机性，共享IID配置不代表各版本会得到完全相同的bootstrap排序。

## 终端命令

在仓库根目录，串行运行全部五版：

```bash
bash scripts/run_twitter_ablation.sh all
```

中断后继续：

```bash
bash scripts/run_twitter_ablation.sh all --resume
```

也可先运行完整版本，再逐项运行，避免一次启动全部：

```bash
bash scripts/run_twitter_ablation.sh full
bash scripts/run_twitter_ablation.sh fixed_knobs
bash scripts/run_twitter_ablation.sh fixed_regions
bash scripts/run_twitter_ablation.sh uniform_budget
bash scripts/run_twitter_ablation.sh nei_only
```

默认输出 `artifacts/twitter_ablation_50_v2/<variant>/`。可用环境变量`TWITTER_ABLATION_DIR`
更换整批输出目录，避免不同代码版本混用。不要在此时另开同一数据库的基线实验。
全部命令均复用已有Twitter模板，不重新导入数据。

运行中或结束后汇总：

```bash
.venv/bin/python scripts/analyze_twitter_ablation.py
```

输出`analysis/REPORT.md`、`summary.csv`、`diagnostics.json`、`best_tps.png/pdf`和
`validation_tps.png/pdf`。缺少完整三次成功复测时，中位数记为pending/invalid，
不会只选择成功样本计算复测结果。

重点比较最终复测、达到目标吞吐的速度、增益来源、换参覆盖、范围更新及实际候选数量。
若完整版本与某消融基本一致，先确认被移除机制在完整版本中是否真的触发，再讨论贡献。
不要仅凭哪个单次峰值最高就调整超参数或宣称机制有效。

## 完整历史与前缀缓存（2026-11-05更新）

当前实验请求由`DeepSeekLLMClient`直接调用DeepSeek API；使用DeepSeek Harness进行
交互不会自动改变脚本的调用链。本次优化在专家请求构造层实施。

- 初始专家筛选、逐轮提议和联合评议均接收当前运行的**全部已完成评测**，不再只发最近5次。
  历史包括共享IID配置、每次完整配置、实测指标、utility、状态、来源、耗时及锚点编号。
  失败评测也保留，但明确标注不可作为吞吐量证据；不会引入其他方法的运行结果。
- 与专家作用域相关的历史只另外提供完整trial编号索引，不重复发送配置副本，也不再截取最近8次。
- 请求排列为：固定system指令→工作负载/全部参数定义→按轮次追加的完整历史→
  当前作用域、锚点、专家身份、候选配额等动态信息。所有JSON嵌套字段采用稳定序列化。
  各专家在同一轮共享较长前缀，下一轮复用已有历史部分；校验重试仅在末尾追加纠错信息。
- 无须设置虚构的缓存开关，也不发送付费预热请求。服务端缓存并不保证命中，实际收益看usage。
  输入历史增加后，即使命中比例提高，也不保证总输入成本一定降低。

每次响应控制台打印`[LLM CACHE]`，记录服务端返回的命中/未命中token数、命中率、
历史长度和耗时。请求日志为各版本`llm_cache/cognitune_v3/request_metrics.jsonl`。
本地复用已有回复单独记为`local_response`，不冒充服务端前缀缓存命中；校验失败后的
API重试也计入统计。缺少服务端命中字段时显示unknown，不报告虚假的0%或100%。

汇总实际缓存情况：

```bash
.venv/bin/python scripts/report_llm_cache.py artifacts/twitter_ablation_50_v2
```
