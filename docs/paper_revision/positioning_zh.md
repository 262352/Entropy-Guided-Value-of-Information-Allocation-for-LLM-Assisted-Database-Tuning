# CogniTune：投稿定位与前文重构建议

2026-11-04

本文讨论研究定位，不把尚未验证的设计写成已证明的优势。配套
`cognitune_frontmatter.tex` 是可替换原稿标题、摘要、引言及相关工作的英文稿，
`additional_related_work.bib` 补充三个相关工作的引用。原稿的中文技术正文暂未覆盖。

## 1. 推荐定位

**CogniTune: Learning Effective Search Spaces for LLM-Assisted Database Tuning**

中文可译为“CogniTune：面向大语言模型辅助数据库调优的有效搜索空间学习”。
短标题：Learning Effective Search Spaces for Database Tuning。

一句话主张：**将专家知识转化为可执行搜索假设，并用执行证据联合修正其参数组、取值提议和搜索投入。**

“动态”描述系统行为，“学习有效搜索空间”给出优化对象；“可执行搜索假设”提供方法层面的承载对象。
标题不需要列出熵、多智能体、动态选参三个工具。CogniTune 名称可以保留。

这里的学习表示从执行数据更新机会判断和提议机制，不意味着训练或微调LLM，
也不声称学习到了最优低维流形。

## 2. 主问题应如何重写

原问题“如何联合修改搜索结构和专家预算”依赖特定多专家架构，容易成为工程接口问题。
更基本的问题是：

> 在有限真实评测预算下，如何依据当前搜索过程产生的选择性证据，持续修正下一步值得投入的搜索方向？

接着定义一个搜索方向的三个属性：

- C：改变哪个参数组，包括必要的交互伙伴；
- R：对这个组提出什么取值及联合变化方式；
- w：这个方向获得多少候选生成投入。

一个假设不仅是“内存专家认为缓冲区重要”，而是“在当前参考配置下，对特定参数组的
某个区域继续细化/移向另一侧/开展联合调整”。其价值是尚有多少条件改进机会。
多专家为这些对象提供知识；代理模型和真实执行负责评估与修正。

搜索历史具有选择性：没采到、没执行、换过上下文，均影响能够作出的判断。
不能由“历史上贡献小”直接推出“没有继续调整的价值”。这是问题动机，
不是已经建立了因果识别或无偏估计理论。

## 3. 三个挑战与三项贡献

### C1：样本中的重要性不足以决定当前的继续投入价值

重要参数可能已在当前工作点附近优化充分，暂时不明显的参数可能需要改变搭档才有收益；
也可能只是缺少真实探索。挑战是把条件潜力和证据覆盖一起用于结构决策。

对应贡献：**面向可执行搜索假设的条件机会估计。**
解释参考配置、小组条件改进、有限审计范围、模型不确定性及实际测量覆盖如何共同参与判断。
不把有限探针概率称为整个合法空间的收益上界。

### C2：参数组变化与取值提议相互依赖

只改变活动参数名单、却沿用旧区域，可能让新增方向没有合适取值；
只改变各旋钮的边缘范围，也可能破坏有意义的联合变化。挑战是保持一个假设的可执行语义，
并让结构与区域在证据积累过程中协调演化。

对应贡献：**执行证据驱动的结构—区域协同适配。**
写清什么证据支持驻留、替换、回访、平移、细化或扩张，哪些变化导致旧局部证据需要重审。
每6轮复核、最多换2个等数值是实现设置和敏感性分析对象，不能代替贡献。

### C3：预算分配影响可观测证据，试验选择又影响下一次分配

不同方向的候选数、重复度和实际执行机会不一样。需要比较的是具体搜索假设，
而非给专家身份赋予永久能力分数。

对应贡献：**基于可比较机会的评测—候选预算协同分配。**
等规模可行审计集控制最直接的候选数量效应；预测收益约束下的信息选择研究的是
一次执行能否帮助后续搜索分配。等量审计不自动提供对完整提议分布的无偏估计。

三项贡献的联系是：先判断具体方向的机会，再修正其结构与覆盖，最后决定下一次执行
和后续候选的投入。多专家贯穿提议过程，不单独充当第三项创新。

## 4. 和最相关工作的准确区别

### DOT

DOT已经在线更新活动参数，不能再用“对手只初始化选一次，我们动态选”作为总差异。
原论文的主要控制对象是当前参数集合，采用RFECV与LRT组织筛选和扩展。
我们的区别应落在**带有取值提议的参数组搜索假设及其联合修正**，并研究当前条件机会与
实际执行覆盖如何影响后续投入。

不要断言RFECV不能表达交互或DOT永远不能重新考虑参数。重要性估计与条件机会是不同目标，
这比声称某个统计工具“无能”更准确，也更容易通过实验验证。

原文第4节：https://arxiv.org/html/2603.15540v1

### MCTuner

MCTuner已经根据执行反馈动态分解空间、通过UCB选择子空间，并在每轮从根重建树。
原稿“分区后无法返回”的描述应删除。
我们的区别是**把知识生成的提议本身作为可修正对象**：参数组、提议区域及候选投入随执行
反馈变化；不是把“动态”本身当作独有能力。需要区分当前选中的树区域与最初给定的搜索域。

原文第5—6节：https://arxiv.org/html/2509.06298v1

### 更广的优化文献

- TuRBO已有局部模型与全局采样分配，不能将“调整局部区域并分配预算”泛称为首次提出。
- ESP已有信息论驱动的BO组合，不能将“熵选择候选/策略”单独包装成原创主张。
- LLAMBO已经让LLM依据历史评测参与BO，不能将“每轮把反馈发给LLM生成候选”当作区别。

来源：
https://proceedings.neurips.cc/paper/2019/file/6c990b7aca7bc7058f5e98ea909e924b-Paper.pdf
https://arxiv.org/abs/1406.4625
https://proceedings.iclr.cc/paper_files/paper/2024/file/84b8d9fcb4e262fcd429544697e1e720-Paper-Conference.pdf

当前定位是一个研究主张，不是检索完备性或优先权结论。投稿前还需要系统整理动态子空间、
变量选择和LLM候选生成方面的最近工作。

## 5. 原稿需要删除或改变的论断

1. “Execution feedback is only used to update performance prediction”不准确。
   改为承认已有在线结构/区域控制，再指出本文研究的具体联合决策。
2. “High entropy should acquire evidence; low entropy should exploit”过度简化。
   确定无收益的方向同样低熵，却不值得利用；高熵方向也未必值得花费执行预算。
   应同时考虑收益、决策相关性和剩余预算。
3. “C1: selection is not revised after initialization”没有覆盖DOT，也没有形成新的研究挑战。
   改为重要性、条件机会和证据覆盖之间的区别。
4. “MCTuner cannot return to an excluded region”混淆树选择和不可逆删除，应删除。
5. source layer / expert candidate budgets改成search-hypothesis allocation，专家保留为知识来源。
6. 摘要结尾“本文给出设计，系统实验留待完成”放到工作稿版本说明，不放进投稿摘要。
   实验完成后补真实结果句，不能现在填写未获得的提升幅度。
7. 文中“粒度自适应”若指单独的步长/网格学习机制，目前实现没有完整支持，应改写为
   实际存在的中心/尺度和采样机制，或者实现后做消融，不能用连续采样代替其证据。
8. 原始片段有三次title声明及不一致的running title，替换稿已统一。

## 6. 当前代码与强论文主张之间的缺口

- stable-v1已有参数组标签、等量审计、结构驻留、真实覆盖和区域更新，但目前仍包含
  大量启发式阈值。不能把“同时有三个控制开关”直接等同于新的统一优化算法。
- 需要明确定义假设的标识与上下文版本。当前group键以参数名为主；如果区域、联合方式或
  锚点明显变化，应说明机会估计如何遗忘或重置，避免旧机会被当成新假设的可靠能力。
- 可行化后实际改变的参数组和原始建议组可能不同。方法与日志应能区分它们，并给出
  审计来源和预算归属的规则。
- 真实覆盖阈值只说明安排了测量，不是“已充分探索整个区间”的统计证明。
- 预测收益门槛仅约束代理采集值，不是实际TPS的性能下界。
- 旧Twitter日志中的过度更替来自我们的旧实现，不能用来证明DOT或MCTuner也有这个缺陷。
- 原组Twitter峰值未优于MCTuner；stable-v1的两种子Mock合成对照也没有超过legacy。
  这些事实不能支持“已证明更好的最终性能”。新一组实测和机制消融仍然必要。

这些是决定文章能否站住的研究工作，不应通过更强的形容词掩盖。

## 7. 怎样组织发表所需的证据

### 机制动机

用可控低维实例验证四种具体情形，再在DBMS上寻找对应现象：

- 全局重要参数已接近当前最优，另一个较弱参数却有较大的剩余机会。
- 单参数调整收益小，联合调整存在可验证收益。
- 建议区域偏移，扩大/移动与只在旧范围继续采样有不同效果。
- 候选数量不同导致机会比较变化，等量审计与简单池最大值有何差异。

必须和有竞争力的已有机制比较，不能只修复一个人为削弱的自有基线。

### 统一闭环的必要性

保留同一候选生成接口、同一GP、同一初始数据和相同预算，比较：

- 固定结构与固定区域；仅改结构；仅改区域；两者一起改。
- 均匀分配；池最大值分配；固定审计机会分配；加入信息选择的分配。
- 专家身份分配与具体搜索假设分配。
- 相同全域探索比例，排除提升仅来自额外随机逃逸的可能。

不只看最高TPS，还看达到共同性能目标的评测次数、最终复测中位数、执行/候选/token成本，
并记录同一驻留期未测即退出率、重入收益、区域移动后的收益、预算改变是否改善后续候选。

### 完整对照

DOT、MCTuner、合适的局部BO、LLM候选生成或简单组合基线都应纳入。
DOT的主设置初始epoch为5乘以初始旋钮数，只有50轮可能尚未完成其一次结构更新。
因此50轮可以作内部诊断，完整论文还应采用使各方法能实际运行核心机制的预算曲线，
例如100/200轮，并同时比较时间预算。任何缩短初始化或修改epoch的适配均需说明。
采用多随机种子、共享初始化协议、真实重复测量和对最终配置的独立复测。

## 8. 全文应如何排列

1. 引言：昂贵评测下的搜索投入决策 → 重要性不等于条件机会 → 选择性反馈 → 搜索假设。
2. 问题定义：合法域、参考配置、假设及其覆盖/投入、数据库和LLM预算。
3. 系统概览：提出假设—估计机会—选择执行—修正假设的单一闭环。
4. 假设表示与条件机会估计：语义、可行化、有限审计、覆盖、上下文。
5. 结构与区域协同更新：继续/替换/回访，以及区域细化/平移/扩展。
6. 评测与候选预算耦合：机会变量、信息选择、反馈分配、成本与末期利用。
7. 实验：总体性能、三类机制的必要性、误导先验/噪声/预算敏感性、实际开销。
8. 相关工作与结论：围绕决策对象对照已有工作，结论只总结得到支持的发现。

写作目标是让审稿人能够复述“这个系统如何学习该继续搜索哪里”，而非记住三个互相独立的模块。
