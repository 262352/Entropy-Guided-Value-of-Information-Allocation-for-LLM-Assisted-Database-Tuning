# Twitter：有效搜索空间控制修正版 stable-v1

本版本针对已完成的 Twitter 实验中发现的三个问题：每轮平均替换10.4个活动参数、
大量参数在没有真实调整前退出、区域半宽始终没有改变。旧实验目录和旧策略保留。
本文件描述实现与验证，不宣称新版已经在真实 Twitter 上超过旧版或 MCTuner。

## 启动新的50轮对比

```bash
cd /root/OpAdviserPrivate/Entropy-Guided-Value-of-Information-Allocation-for-LLM-Assisted-Database-Tuning
bash scripts/run_twitter_stable.sh both
```

断点续跑：

```bash
bash scripts/run_twitter_stable.sh both --resume
```

输出为 `artifacts/twitter_pair_50_stable_v1/`。如需探索性地容忍默认性能波动，显式添加
`--allow-unstable-baseline`；数据库基础设施故障与前12轮评测失败仍会中止。

只单独运行新版可用 `bash scripts/run_twitter_stable.sh cognitune_v3`。
比较时仍应串行完成新版和 `mctuner_official`，避免同一实例上的资源竞争。

每种方法仍为50次真实评测总预算，包括默认配置及9个IID随机配置组成的共享10点初始设计。
复用上一组的**初始配置文件、MCTuner专家选择和请求缓存**；默认配置、初始点、调优配置及
最佳配置验证全部重新测量。不会复用上次的TPS、新版反馈请求或控制器状态。
工作负载、数据库模板、指标、预热15秒/测量60秒及持久化设置与上一组一致。
各方法另做3次最佳配置验证、3次默认漂移检查。仅新建文件夹，不覆盖旧结果。

## 搜索结构

- 在共享初始评测之后，4名专家先根据实际初始数据提出重点旋钮，避免冻结GP早期不稳定排序。
  该准备过程与每轮提议分开记录；额外的4次专家请求计入请求日志。
- 活动维度上限按剩余评测预算确定：`min(active_target, max(6, adaptive_budget // 4))`，
  默认40次自适应评测对应10维活动集。该比例是可检查的实现选择，尚需敏感性实验。
- 每6次评测才进行结构复核；单次最多换入2个旋钮，保留核心内存参数和专家领域覆盖。
- 退出候选至少驻留6轮，获得2次有意义的真实局部调整，覆盖至少2个不同取值（布尔/二值参数只有一个替代值时为1个），并在新上下文下
  有过真实验证。代理预测、生成候选和全域参考配置不计入这个局部覆盖证据。
- 有依据的低潜力、可信的替代方向或跨复核持续的机会优势可触发替换。
  对长期停留且仍不明确的方向，允许小规模替代验证，记录为
  `scheduled_alternative_verification`，不宣称原方向已经耗尽。
- 单参数潜力弱，不能拆开仍有较强联合潜力的已确认参数组。
- 最优锚点显著变化后清空旧局部区域比较窗口，保留历史执行事实，但要求新的局部证据后
  才能退出，不再把全部探索次数和驻留时间一并抹掉。

## 候选与区域

- 专家给出明确稀疏补丁与区域；程序围绕参数组生成候选，不再独立随机选择1—4个旋钮拼接。
  对明确补丁保留联合参数集合和数值方向；原始明确补丁也进入候选池。
- 预算和决策熵的比较对象改为 `group:<旋钮名组合>` 搜索假设；相同参数组可以由多个专家
  提出。每个假设有相同规模的独立审计样本，其大规模候选配额按后验机会更新。
- 专家身份保留为知识来源，下一轮提示中提供对应配额摘要及与其参数有关的历史执行记录。
- 数值半宽初始接受专家建议并限于[0.05,0.25]；后续按真实局部样本更新，最低0.025、最高0.5。
  重复的有效边界改进支持扩张；充分覆盖区域两侧且局部平台或内部改进支持细化。
  更新不再同时依赖“GP极端确定”和“LLM请求动作”两个门槛。
  局部平台细化是一种搜索控制启发式，不等同于整个合法域收益耗尽。
- 每3个自适应步骤预留一个实际局部覆盖评测，优先尚未得到执行机会的活动方向，并补充
  区域另一侧的证据。覆盖开销计入50次预算；保留独立全域参考和非活动方向回访。
- 最后6次评测使用纯qLogNEI挑选，不再做信息增益选择、固定覆盖或回访。

## 诊断与检查点

仍在 `runs/cognitune_v3/seed_0/` 下输出，但 `summary.json` 的 `method_version` 为
`stable-space-v1`，`protocol.json` 的 `search_policy` 为 `stable-v1`。
旧策略与新策略不能混用同一个目录或检查点。

`round_diagnostics.jsonl` 新增：

- `structure_bootstrap`：初始专家重点方向及其选择依据。
- `structure_control`：是否复核、换入/换出、原因、驻留时间、执行覆盖及不同取值数。
- `actual_execution_coverage`：真实局部评测覆盖，不把代理审计当成测量。
- `hypotheses` / `hypothesis_quotas`：参数组、提出专家、明确补丁及其候选预算。
- `generation_kinds`：明确LLM补丁、按组采样、覆盖、参考或联合提议，避免混淆来源。
- `range_updates`：实际半宽更新、触发原因及所用真实样本。
- `anchor_context_reset`：锚点变化后局部证据失效的记录。

检查点包含全部新增结构、区域证据、候选分配与程序随机数状态，续跑不重复已有评测。
稳定策略只接受完整匹配的检查点；遇到缺失的关键控制状态会停止而不是猜测。

### 类别参数接口修复（2026-11-04）

`wal_sync_method` 等类别、布尔及枚举参数使用合法选项集合，不使用数值半宽或类别索引。
专家的 `values` 会进入按组候选生成；显式中心按实际选项处理，不经过数值中心移动限幅。
非数值区域中的多余 `halfwidth` 被移入接口修复审计；明确 `hold/pause` 且中心为空或
误填数字时，仅保留当前锚点的合法选项，绝不把数字解码成某个类别。未知字符串、非法
选项集合或无法解释的迁移仍会触发校验和重试。原始回复保存在LLM缓存，修复写入
`interface_repairs` 和缓存的 `scope_repairs`。

本次中断时已完成28次评测，检查点与观测一致。使用
`bash scripts/run_twitter_stable.sh both --resume` 从第29次继续；前28次记录保持原样。
续跑后的候选生成包含这次修复，分析时应保留该代码变更边界。

## 本轮验证的范围

单元及集成检查覆盖驻留、实际探索覆盖、交互组保护、双侧区域更新、参数组候选、预算守恒、
检查点续跑、旧方法回归及实验准备隔离。额外执行两个种子的完整50轮合成检查，使用后验样本128、幻想8，均未调用
真实数据库或远程LLM；真实入口默认后验样本256、幻想16。其记录在 `artifacts/stable_offline_check_release/`。

最终合成检查的每轮平均换入数约为0.13和0.18、每轮最多2个；全部退出都具备至少2次真实
局部调整，每个种子出现3次区域更新。相比旧实现的每轮约11.7次更替，机制已按预期稳定。
但这两个采用Mock专家的合成对照中，新版最终值仍低于旧策略，因此这些结果只能验证
控制机制及完整执行，**不能作为真实性能提升或超过MCTuner的证明**。
需要新的Twitter实测和最终复测判断稳定性带来的收益与探索损失之间的取舍。
